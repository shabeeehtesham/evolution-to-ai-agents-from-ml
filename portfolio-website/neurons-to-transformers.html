Live Demo: Retrieval-Augmented Generation

This runs Project 4's real pipeline — a from-scratch TF-IDF vector database (NumPy in Python, re-implemented in JavaScript here) retrieving from the same 17 real, cross-checked Shakespeare facts the CLI agent uses, then the same local keyword-extraction engine the CLI falls back to when no Gemini API key is present. Ask a question: watch it actually retrieve the most relevant facts by real cosine similarity, then generate an answer built only from what it retrieved.

This is where the story from tabs 1–3 lands. Self-attention (tab 3) let a Transformer weigh every earlier token at once instead of one step at a time like the RNN/LSTM — that parallel, long-range context is the core mechanism behind every modern large language model (LLM). It's why LLMs write fluent, coherent text. But an LLM's knowledge is frozen at training time, and it can misremember. RAG is the fix: instead of trusting only what the model memorized, retrieve real facts first, then let the model generate an answer grounded in them — verifiable, not just plausible-sounding.
